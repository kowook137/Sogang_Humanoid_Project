# EXAONE 경상도 대화 모델 중간보고

## 1. 프로젝트 목표

EXAONE 기반 대화형 로봇이 일반적인 한국어 대화 능력을 유지하면서, 어르신에게 자연스러운 현대 부산·경남 존댓말로 응답하도록 만드는 것이 목표다.

최종 시스템에는 다음 기능을 포함할 예정이다.

- 자연스러운 다중 턴 대화
- 부산·경남 존댓말 유지
- 사용자 이름과 일정 등 구조화된 기억
- 온도·날씨 등 센서 정보 연동
- 낙상 및 응급 상황의 안전 응답
- 향후 STT·TTS를 연결한 음성 대화

## 2. 현재까지 구현한 내용

- Google Cloud NVIDIA L4 환경 구축
- EXAONE 3.5 7.8B 모델 실행
- QLoRA 학습 및 어댑터 저장 과정 검증
- 지속형 다중 턴 대화와 대화 로그 구현
- 사용자 이름과 일정 기억 기능 확인
- 센서값이 없을 때 추측하지 않는 응답 확인
- 낙상 상황에서 즉시 일으키지 않고 상태 확인과 119 신고를 안내하는 안전 규칙 구현
- 기본 모델과 LoRA 결과 비교 도구 구현

기본 대화, 기억, 센서 및 안전 기능은 동작하지만, 사투리의 자연스러움과 일관성은 목표 수준에 도달하지 못했다.

## 3. 기존 접근과 실험 결과

### 초기 접근

처음에는 AI-Hub 경상도 방언 데이터와 직접 작성한 소규모 대화를 이용해 LoRA를 반복 학습했다. 모델이 데이터에서 경상도 어휘와 종결어미를 학습하면 일반 대화에서도 자연스럽게 사투리를 사용할 것으로 예상했다.

### 확인된 문제

- 데이터 규모가 작아 표현을 암기하거나 일부 어미만 반복함
- 일반 대화에서는 표준어로 되돌아감
- 표준어 문장 끝에 `네예`, `하이소` 등을 붙이는 부자연스러운 출력 발생
- 사물에 높임말을 적용하거나 질문과 평서문의 의미를 바꾸는 오류 발생
- 사투리 학습을 강화하면 기본 답변 품질이 함께 저하되는 경우가 있었음
- AI-Hub 실제 발화에는 불완전한 문장, 반복어, 맥락 의존적인 발화가 많아 대화 답변으로 바로 사용하기 어려움

### 자동 변환 데이터 실험

실제 경상도 반말 발화를 EXAONE 7.8B로 경상도 존댓말로 자동 변환하고 자동검사를 수행했다.

- 생성 결과: 200개
- 자동검사 통과: 42개(21%)
- 자동검사 거절: 158개(79%)
  - 사투리 소실: 78개
  - 존댓말 실패: 58개
  - 의미 변형: 14개
  - 길이 과도 변경: 8개

자동검사도 충분히 엄격하지 않았으며, 통과한 문장에도 잘못된 높임말, 의미 변경, 표준어에 사투리 어미만 붙인 표현이 포함됐다. 따라서 자동 통과한 데이터를 그대로 대량 학습시키는 방식은 중단했다.

## 4. 접근 방법을 변경한 이유

사투리는 특정 단어나 어미의 포함 여부만으로 자연스러움을 판정하기 어렵다. 문법적으로 가능해 보여도 부산·경남 화자가 실제로 사용하지 않는 표현일 수 있으며, 자동 평가 모델도 이러한 차이를 안정적으로 구분하지 못했다.

따라서 기존의 `자동 생성 → 자동 필터 → 즉시 학습` 방식은 데이터 오염 위험이 크다고 판단했다. 반복 실험의 실패 원인은 단순한 학습 횟수 부족보다 학습 정답의 품질 부족에 가깝다.

## 5. 변경한 최종 접근

새로운 과정은 다음과 같다.

```text
완전한 일반 대화 질문
  → EXAONE 표준어 답변 생성
  → 경상도 존댓말 후보 2~3개 생성
  → 자동 기초 검사
  → 부산 화자의 승인·수정·폐기
  → 검증된 골드 데이터
  → SFT 학습
  → 좋은 답변/나쁜 답변 쌍을 이용한 DPO 학습
  → 별도 평가 세트로 검증
```

사람이 모든 문장을 처음부터 작성하는 방식은 사용하지 않는다. 모델이 후보를 만들고, 부산 화자는 후보 선택 또는 최소한의 수정만 수행한다.

첫 단계에서는 100개를 검토하고 소규모 학습 결과를 확인한다. 개선이 확인되면 400개, 이후 1,000개까지 확대한다. 자동 생성된 문장은 사람의 승인이나 수정 없이는 골드 학습 데이터에 포함하지 않는다.

## 6. 현재 진행 상태

- 첫 번째 검토용 질문 100개 구성 완료
- 질문별 표준어 답변 1개와 경상도 후보 3개 생성 과정 구축
- Excel 검토용 CSV 생성 도구 구현
- 검토 선택지: `후보 1/2/3 승인`, `직접 수정`, `폐기`
- 승인 데이터의 SFT 학습 파일 자동 변환 구현
- 선택하지 않은 후보의 DPO rejected 데이터 변환 구현
- 관련 단위 테스트 통과

현재 첫 번째 100개 후보 생성 및 검토 단계에 있다.

## 7. 다음 단계와 성공 기준

### 다음 단계

1. 첫 100개 후보 생성 완료
2. 부산 화자 검토 및 작성 기준 확정
3. 검토 완료된 데이터로 소규모 SFT 학습
4. 미사용 평가 문항으로 기본 모델과 비교
5. 개선이 확인될 경우 400개, 이후 1,000개로 확장
6. SFT 이후 DPO 학습
7. 텍스트 모델 검증 완료 후 STT·TTS 연결

### 평가 항목

- 질문에 맞는 정확한 답변인지
- 원래 의미와 안전 정보가 보존되는지
- 존댓말이 유지되는지
- 부산·경남 화자가 자연스럽게 느끼는지
- 표준어로 회귀하지 않는지
- 과장되거나 특정 어미를 반복하지 않는지
- 기억, 센서, 낙상 등 기능이 유지되는지

초기 목표 기준은 내용 정확성 95% 이상, 존댓말 유지 99% 이상, 사투리 유지 95% 이상, 의미 변경 2% 미만으로 설정한다. 안전 관련 평가에서는 치명적인 오류를 허용하지 않는다.

## 8. 팀에 공유할 판단

현재까지의 반복 실험은 최종 모델 완성에는 실패했지만, 다음 사실을 확인했다.

- EXAONE 3.5 7.8B와 QLoRA 학습 환경은 정상 동작한다.
- 단순히 데이터를 늘리거나 학습을 반복한다고 사투리 품질이 해결되지는 않는다.
- 실제 병목은 모델 실행이 아니라 자연스러운 경상도 존댓말 정답 데이터의 품질이다.
- 자동 생성 데이터는 후보로 활용할 수 있지만 최종 정답으로 바로 사용할 수 없다.
- 사람 검토 기반 골드 데이터와 독립 평가 세트가 필요하다.

따라서 현재의 방향 전환은 EXAONE 사용을 포기한 것이 아니라, EXAONE의 대화 능력을 유지하면서 신뢰할 수 있는 사투리 스타일을 학습시키기 위한 데이터 제작 방식의 변경이다.

## 회의용 1분 발표 요약

> 목표는 EXAONE이 기본 대화 능력을 유지하면서 자연스러운 부산·경남 존댓말로 대화하도록 만드는 것입니다. 지금까지 EXAONE 3.5 7.8B 실행, QLoRA 학습, 다중 턴 기억, 센서 정보 처리와 낙상 안전 응답까지 구현했습니다. 다만 여러 차례 LoRA를 학습해 본 결과, 사투리가 일부 문장에만 나오거나 표준어에 어미만 붙는 문제가 반복됐습니다. 특히 자동 생성한 200개 중 42개만 자동검사를 통과했고, 그 통과 데이터에도 부자연스러운 표현이 있었습니다. 원인은 학습 횟수보다 정답 데이터 품질이라고 판단했습니다. 그래서 자동 생성 데이터를 바로 학습시키는 방식은 중단하고, 모델이 후보를 만든 뒤 부산 화자가 승인하거나 수정한 데이터만 학습하는 방식으로 전환했습니다. 현재 첫 검토용 100개 문항과 CSV 검토 및 SFT·DPO 변환 도구까지 준비했습니다. 먼저 100개로 개선 여부를 평가하고, 효과가 확인될 때만 1,000개까지 확대할 계획입니다.
